Human.exe -- Developer Status Report

Project: Human.exe Academic Companion App  |  Date: April 16, 2026  |  Platform: React Native + Expo SDK 54  |  Team: Michael Enaye, Jialin Fu, Jaya Surya V.M., Billy Presume, Yuting Yan

1. Overview

Human.exe is a cross-platform iOS/Android mobile app designed to help Johns Hopkins University students overcome procrastination by reducing the psychological barrier to task initiation. The core mechanic is AI-powered task decomposition: given a vague assignment, the AI breaks it down into 4-6 small, concrete, immediately actionable steps. The research basis is 52 surveys and 9 interviews at JHU showing that initiation (not time management) is the primary barrier to academic productivity.

3. Architecture Overview

File Structure (key paths)

  • app/(tabs)/ -- The 5 tab screens: Home, Tasks, Timeline, Stats, Settings
  • app/task/new.tsx -- 3-phase AI task creation modal
  • app/task/[id].tsx -- Task detail + step management
  • app/chat.tsx -- AI chat companion screen
  • services/ai/ -- Provider interface, factory, all provider implementations
  • services/firebase/ -- Firestore and Auth wrappers
  • services/mock/ -- Full in-memory backend for offline/demo use
  • store/ -- Zustand stores: authStore, taskStore, settingsStore
  • components/mascot/HumanMascot.tsx -- Animated sloth mascot (Sid)
  • constants/ -- colors.ts, spacing.ts, typography.ts (design tokens)

AI Provider Architecture

All AI providers implement the AIProvider interface from services/ai/types.ts:

  • decomposeTask(title, description, context?)
  • regenerateStep(taskTitle, stepTitle, reason?)
  • getStepEncouragement(taskTitle, completedStep, stepsLeft)
  • chat(messages, systemContext?)

OpenAIProvider is the base class for DeepSeek and Ollama. Both override only the constructor (setting baseUrl and model). The factory (services/ai/factory.ts) reads settingsStore and returns the correct implementation at call time, enabling live provider switching.

Data Flow

  1. App start: useAuth() hook initializes Firebase listener, populates authStore.
  2. Task load: useTasks() hook subscribes to Firestore, populates taskStore.
  3. MOCK_MODE: Firebase and AI calls are intercepted by in-memory mock implementations.
  4. Task creation: new.tsx calls decomposeTask() from services/ai/claude.ts facade, which delegates to getAIProvider().
  5. Task and step CRUD: all screens call updateTask()/updateStep() from services/firebase/firestore.ts, which updates Firestore. The real-time listener updates taskStore, triggering re-renders.

4. Known Issues and Gaps

IssueImpactRecommended Fix
Settings not persisted across restarts High: API keys must be re-entered every session Add expo-secure-store (for API keys) + @react-native-async-storage/async-storage + Zustand persist middleware
focusModeDefault setting not applied at screen load Low: preference toggle does nothing currently In app/task/[id].tsx, initialize focusMode state from useSettingsStore().focusModeDefault
Haptics always fire regardless of hapticFeedback toggle Low: annoying for users who disable it Gate the Haptics.impactAsync() call behind if (settings.hapticFeedback)
Reward field stored but never shown after task creation Medium: reduces the motivational impact of the feature Show the reward string on the task completion screen or as a reminder on the task detail screen
Chat history lost on navigation Low: conversation not preserved between visits Move chat messages to a Zustand chatStore or a lightweight Firestore subcollection
Mock mode banner only in chat — not in task creation Low: task creation flow does not tell user they are on mock AI Show the same setup banner in app/task/new.tsx during the AI generation phase
No push notification support Medium: reduces engagement Add expo-notifications. Schedule a local notification when a task due date is set.
No Google OAuth Low for MVP: guest + email covers the demo Add expo-auth-session + Google provider in Firebase console
Stats page reads from in-memory taskStore only Low: data is correct but if store is cold, charts show empty Ensure useTasks() hook always runs before stats renders (it does via root layout)

5. Configuration Notes

Running the App

  • Install: npm install
  • Start: npx expo start
  • Set MOCK_MODE = true in services/firebase/config.ts for offline development (no Firebase project needed)
  • Set EXPO_PUBLIC_ANTHROPIC_API_KEY in .env to enable Anthropic in dev without entering a key manually

AI Setup for DeepSeek (recommended)

  1. Create an account at platform.deepseek.com
  2. Generate an API key
  3. In the app: Settings > AI Provider > DeepSeek > API Key
  4. The deepseek-chat model (DeepSeek-V3) is the default and performs well on task decomposition

Environment Variables

VariablePurpose
EXPO_PUBLIC_ANTHROPIC_API_KEYOptional Anthropic key loaded at build time (falls back to user-entered key in Settings)

6. Design System

All design tokens live in constants/:

  • colors.ts: Research-backed palette. Primary blue (#3D7EC4) chosen for calm focus. Warm accent for encouragement. All colors have semantic aliases (textPrimary, surface, divider, etc.).
  • spacing.ts: T-shirt size scale (Spacing[1] = 4px through Spacing[20] = 80px). Also exports Layout, Radius, Shadow.
  • typography.ts: FontSize enum + Typography component with variant system (heading1-4, body, bodySmall, label, caption).

7. Testing Status

No automated tests are currently in place. The architecture is unit-testable (providers are pure classes, store is Zustand, all Firebase calls are in a separate service layer), but test infrastructure has not been set up. Recommended additions:

  • Jest + @testing-library/react-native for component tests
  • Unit tests for parseTaskBreakdown() in services/ai/prompts.ts (most critical path)
  • Mock provider tests for AI fallback behavior
